# 테마 라벨 점검 (2026-08-26 아침)

2026-08-25 밤에 고친 테마 라벨이 다음 장에서 제대로 찍히는지 확인하는 절차입니다.

점검을 다시 합니다.

## 무엇을 고쳤나 — 커밋 `7a2ca7c`

아이티센글로벌과 비트플래닛이 `SI(시스템통합)` 카드 하나에 묶여 나왔습니다. 그날 SI는
**-0.58%p로 두 종목의 테마 중 가장 나빴고**, 비트플래닛을 상한가로 민 것은
가상화폐(+5.07%p)였습니다. 원인이 둘이었습니다.

1. **판정이 크기를 버렸습니다.** `ORDER BY ... b.theme_no ASC` — 조금이라도 오른
   테마 중 번호가 가장 작은 것이 이깁니다. SI는 no.17이라 늘 이겼습니다.
   → `s.theme_move DESC`로 바꾸고 theme_no는 동점 처리로만 남겼습니다.
   (`src/providers/naver-themes.mjs`)

2. **사전이 하루 종일 낡아 있었습니다.** 라벨은 분봉을 저장할 때 그 표본에 **함께
   찍히는데**, 사전은 서버 시작 때와 15:50 전 종목 훑기 때만 읽었습니다. 08:00에 뜬
   서버는 어제 상태로 하루를 보냅니다 — 08-25에 두 종목의 08:00~15:36 표본 350개가
   전부 SI를 달았습니다.
   → 수집기가 10분마다 다시 읽습니다. (`src/collector.mjs` `startThemeRefresh`)

회원 수 바닥도 3 → 8로 올렸습니다. 크기순으로만 고르면 3종목짜리 테마가 평균이 흔들려
늘 이깁니다(이노메트리 → `유리 기판`, 엑시콘 → `CXL`). 15로 올리면 반도체 라벨은
나아지지만 `가상화폐`(표본 12종목)가 잘려 비트플래닛이 `클라우드 컴퓨팅`으로 갑니다 —
고치려던 바로 그 문제입니다.

## 08:12 — 프리마켓 첫 분봉

```powershell
# 오늘 표본에 찍힌 라벨
docker exec -i date-platform-postgres psql -U postgres -d date -c "
  SELECT name, theme, count(*) AS n,
         min(observed_at)::time(0) AS first_at, max(observed_at)::time(0) AS last_at
    FROM market_price_samples
   WHERE market='KR' AND session_date=current_date
     AND name IN ('아이티센글로벌','비트플래닛','나노팀','금호에이치티')
   GROUP BY name, theme ORDER BY name;"
```

기대값:

| 종목 | 08-25 (틀린 값) | 기대 |
|---|---|---|
| 아이티센글로벌 | SI(시스템통합) | 스테이블코인 |
| 비트플래닛 | SI(시스템통합) | 가상화폐(비트코인 등) |
| 나노팀 | 전기차 | 전기차 화재 방지(배터리 열폭주 등) |
| 금호에이치티 | 자동차부품 | 전기차 화재 방지(배터리 열폭주 등) |

**08:00에는 오늘 표본이 얇아 `HAVING count(*) >= 8`을 못 넘길 수 있습니다.** 그러면
어제 일봉 스냅샷으로 폴백하고, 라벨이 어제 장 기준이 됩니다. **그건 설계대로이지
버그가 아닙니다.** 다만 폴백인지 live인지 구분해서 봐야 하므로 live 검증은 09:41에
따로 합니다.

같이 볼 것:

- `collector.log`에 `theme refresh failed` 가 있는지
- 08:00~08:15는 **1분 수집 구간**입니다. 빠진 분이 있으면 안 됩니다 — 그 시각의
  분봉은 나중에 받아올 방법이 없습니다
- `/api/market-board`의 `krPairTrades` 카드 이름에 `SI(시스템통합)`가 남아 있는지

그리고:

   "오르지도 않은 테마"가 라벨이 된 사례가 또 있는지.
2. 카드별 `themeMove` 중앙값. **1% 미만인데 멤버 한 종목만 크게 오른 카드**가 있으면
   그게 08-25 SI와 같은 유형이니 종목명까지 뽑을 것.
3. 짝꿍매매(`krLimitPairs`)의 1등주와 2등주가 **같은 테마 이름**으로 묶이는지.
   08-25에는 금호에이치티(자동차부품)와 나노팀(전기차)이 다른 이름이었습니다.

## 실패하면

라벨이 여전히 SI거나 판정값과 표본값이 어긋나면, 고치기 전에 **어느 쪽이 문제인지**
먼저 가릅니다.

- 판정 자체가 SI를 고르면 → `naver-themes.mjs`의 ORDER BY와 `minimumThemeSample`
- 판정은 맞는데 표본이 낡았으면 → `collector.mjs`의 `startThemeRefresh`가 도는지
  (`themeRefreshIntervalMs`, 그리고 `isCollecting(now)` 안에서만 불린다는 점)

**이미 저장된 표본은 사전을 고쳐도 바뀌지 않습니다.** 그날 라벨이 틀렸으면 그날은
그대로 가고 다음 장부터 맞습니다.

## 손대지 말 것 — 이미 반증됐습니다

테마 귀속을 자동으로 판정하려는 시도가 08-25에 다섯 번 실패했습니다. 자세한 내용은
메모리 `theme-card-attribution`, `pair-trade-verdict-kr`에 있습니다.

- 멤버의 선택 테마 ≠ 카드 테마면 제외 → 반도체 카드 8개 중 5개 탈락
- 테마 회원 겹침으로 형제 판정 → 네이버 테마는 배타적이라 반도체↔반도체 장비가 0%
- 이름 토큰 공유 + 겹침 25% → 원전 카드 전멸
- 뉴스로 테마 지목 → 2,255개 중 11개만 닿고 비트플래닛은 그 안에 없음
- 재료(공시) 다른 짝 제외 → 상한가 자리에서 +0.906 vs +1.090%p, 상회율 50%로 동일

그리고 **멤버 문턱은 올리지 마세요.** 익일 시가 갭 기준으로 0~1%짜리 멤버도
+0.210%p(대조군 +0.089%p)입니다. 익일 종가로 재면 정반대 결론이 나오니 구간을 갭으로
맞출 것. (`scripts/measure-theme-coherence.mjs`)
